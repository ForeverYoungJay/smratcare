# 弋阳龟峰颐养中心管理平台——医务部全面功能检查与优化报告

> 检查日期：2026-11-05  
> 检查范围：`admin-web`、Spring Boot 后端、Flyway 迁移、权限配置、自动化测试、当前本机演示环境  
> 测试账号：虚构演示账号 `medical_emp`、`medical_minister`；报告不记录老人隐私数据  
> 结论口径：“页面可打开”只证明读路径和渲染可用，不等于新增、审核、通知、签名和生产数据准确性已验证。

## 1. 执行结论

医务模块已经形成工作台、老人视图、健康监测、电子病历、医嘱与执行、药房、巡诊、随访、急救、外出就医、质量与智能提醒等较完整的产品框架。实际浏览器抽查 12 个关键入口，10 个可正常加载，2 个历史健康档案入口对医务角色返回 403；移动端抽查 4 个页面没有页面级横向溢出。

本次确认并修复 2 个 P0 隐私/越权问题：

1. 通用 `STAFF` 可越过网关进入 `/api/medical/**`、`/api/pharmacy/**` 私有接口；现已统一限制为医务、护理及授权管理角色。
2. 电子病历详情按 ID 查询未限制机构，存在跨机构读取风险；现已同时按记录 ID、当前机构和未删除状态查询。

定向后端回归、前端构建、类型检查、lint、导航检查、RBAC 初始化审计均通过。前端全量单测 183 通过、1 个超时；该用例单独以 15 秒阈值复跑 22/22 通过，判定为全量并发下的慢用例。后端全量 286 个测试中 7 个失败、6 个错误，主要暴露测试库迁移/夹具与当前实体不一致及其他模块既有断言漂移；本次涉及的定向测试全部通过。

当前不能判定“具备开展诊疗、处方、发药等业务的实际资质”。仓库未提供医疗机构执业许可证、核准诊疗科目、医生/护士/药师执业资质或经批准的制度文件。医嘱、药房等模块存在不等于机构已获准使用，正式启用前必须由机构负责人和合规人员确认。

## 2. 代码、接口、数据与权限地图

### 2.1 菜单与页面结构

主菜单以 `/medical-care` 为中心，实际包含：工作台、老人列表、基础疾病、照护任务看板、统一任务中心、健康巡查、用药登记、护理日志、交接班、中医/心血管评估、综合健康账户、护理质量、告警规则、智能告警/规则/调度/设备健康、电子病历、医嘱、医嘱执行、药房、AI 报告、巡诊、随访和急救。

`/health` 下仍保留药品字典、库存/用药配置、用药登记、健康档案、健康数据、巡检、护理日志等历史路由，部分入口已隐藏或由新页面承接，形成新旧双路径。

### 2.2 后端 API 族

| API 前缀 | 主要业务 | 当前边界 |
|---|---|---|
| `/api/medical-care/**` | 工作台、老人 360、评估、巡诊、随访、急救、告警 | 医务/护理及授权管理角色 |
| `/api/medical/**` | 电子病历、医嘱、执行 | 本次补齐网关限制 |

### 2.3 核心数据关系

核心医疗表均以 `org_id` 做机构隔离，以 `elder_id` 关联老人，并普遍带 `is_deleted` 软删除标记。主要链路为：

`老人档案 -> 健康档案/生命体征/巡检 -> 电子病历 -> 医嘱 -> 医嘱执行`

`老人档案 -> 用药配置/用药任务/用药登记 -> 药品目录/批次库存/发药`

`老人档案 -> 巡诊计划/巡诊记录 -> 随访计划/随访记录 -> 异常/急救事件/处置记录`

相关迁移覆盖健康服务、评估、健康档案扩展、电子病历、医嘱与执行、巡诊、随访、急救和抢救记录。测试环境仅加载 40 个迁移，未覆盖当前实体所需的全部列/表，是全量后端测试失败的重要原因之一。

## 7. 操作体验与流程优化

本次没有为了“少点一下”而改变医疗核对步骤。唯一已实施的体验变化是安全边界，对授权医务/护理人员无新增操作；非授权 STAFF 从“请求进入业务层”变为立即 403。

| 工作场景 | 原流程 | 优化后流程 | 减少的步骤 | 实施状态 |
|---|---|---|---:|---|
| 非授权人员访问病历/药房 | 登录后请求可进入控制器 | 网关立即拒绝并返回 403 | 0（安全收紧） | 已实施 |
| 查看 EMR 详情 | 按 ID 直接查记录 | 按 ID + 机构 + 未删除状态查询 | 0（安全收紧） | 已实施 |

## 14. 三岗位最终验收

### 医生

病历、医嘱、执行、药房、巡诊、随访入口容易找到，权限边界比检查前安全。但当前老人列表为空，历史健康档案直达 403，且病历/医嘱签名版本链不足，因此不能认定“可在正式诊疗环境完整使用”。最优先改善是统一老人 360、补签名更正机制和专业资格授权。

### 普通医务人员

工作台能快速看到今日待办、逾期和风险，巡检页信息密度合理，手机宽度基本可用。最大阻碍是个人巡诊/医嘱为 `--`、待办夹杂商城任务、档案入口不统一。应先补责任人口径和权限过滤，不应删掉老人、时间、单位、异常确认等安全核对。

### 医务部主任

主任可看到部门指标、异常、报表、管理和任务分配，较员工多 2 个功能入口；但要判断质量、签名、审核和未闭环任务仍需翻页，且现有演示数据不足以核对报表准确性。应建立“异常—责任人—时限—处置—复核”的统一质量闭环，并让指标卡直达同口径明细。
