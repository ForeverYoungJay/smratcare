# Phase 3B-1 护理部工作台

## 已完成

- 护理员工工作台：本人今日任务、超时/异常、关联长者、最近完成记录、常用护理操作和标准下一步。
- 护理部长工作台：部门今日任务、待分配缺口、风险、重点长者、审批/排班/质量入口和任务分配入口。
- 护理首页指标统一改用 `/api/care/tasks/summary`，不再用医务汇总字段代替护理任务。
- 员工请求强制携带当前登录员工 `staffId`；部长请求保持部门口径。
- 无数据时展示真实空状态，不填充演示数据。
- 状态标签同时使用文字与符号，交互按钮提供键盘焦点样式。

## 数据源

- `/api/care/tasks/summary`：今日任务指标。
- `/api/care/tasks/page`：任务预览、关联长者和最近完成记录。
- 现有路由复用：今日任务、护理计划、护理记录、交接班、护理质量、护理排班和审批。

## 已知后端缺口

- 后端当前没有“按护理人员聚合的任务分配与完成情况”接口。部长版只展示接口可准确提供的任务总数、已分配和待分配数量，并明确提示该限制，不从任务预览推算人员绩效。
- 护理任务查询接口支持 `staffId`，但后端尚未强制普通员工只能查询本人。前端工作台已固定传入当前员工 ID；仍建议后端后续增加基于登录身份的数据范围校验，防止绕过前端参数。

## 验证结果

- 单元测试：29 个测试文件、139 个测试全部通过。
- 导航检查：634 条路由、397 个入口、0 个悬空链接。
- 生产构建：通过。
- 真实浏览器：护理员工和护理部长默认首页、岗位文案、操作入口、员工审批 403、空状态和 1280px 无横向溢出均通过。
- 容器访问日志确认：员工护理请求携带本人 `staffId`，部长护理请求不携带 `staffId`、使用部门口径。
