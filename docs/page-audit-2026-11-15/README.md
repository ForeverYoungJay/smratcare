目前的复杂度主要来自四个方面：同一业务对象按状态拆出多个菜单；多个首页重复提供指标和入口；同一份资料在多处展示甚至维护；页面内容按“标题—说明—指标—筛选—工具条—列表”层层堆叠。

已确认 **6 组重复入口**（财务 4、人事 2），另有市场 3 组默认查询/场景高度重叠。报表、审批、合同、资金账户等还有信息重叠，但其中一些有真实业务或权限差异，不能直接合并。

## 统计和证据口径

- “非隐藏组件页面入口”指路由有页面组件，且自身及父级未设置隐藏；不计纯分组、纯跳转和 RouteView 空壳。页面内部的页签、弹窗不是新的路由页面。
- 隐藏兼容链接与仍在渲染的隐藏页面分别登记。`/system` 虽标记隐藏，但它是系统管理员默认首页，因此在管理员重点清单中单独收录。
- 人事“培训计划”等仍可见的场景跳转也登记在跳转清单；36 指有组件的入口，**不是所有可点击菜单项数量**。
- 完整菜单、默认岗位菜单、工作台快捷入口并不相同。52/40/36 不代表普通员工登录后同时看到这些页面。
- 这是基于当前源码的静态盘点：读取了路由、props、页面模板、相关子组件、动态列声明与 CSS。没有以真实账号逐页登录截图，未测量首屏像素、任务耗时或实际接口返回数据。
- 逐页字段中保留动态表达式；不同角色、场景、数据状态和弹层字段合并登记，不应把这些字段都当成一屏同时出现的内容。
- 重复页面的确定性高于“业务信息重复”的判断。仅共享组件/字段名/金额概念，不足以证明数据集相同。实际可访问范围仍受角色组合、页面白名单、操作权限、后端校验限制。
- 既有阶段文档用于理解背景；当前实现与旧文档不同的地方，以当前路由和组件为准。

## 1. 先分清管理员的两种身份

| 对象 | 默认首页 | 主要职责和入口 | 当前呈现 |
|---|---|---|---|
