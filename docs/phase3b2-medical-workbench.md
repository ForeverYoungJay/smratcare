# Phase 3B-2 医务部工作台

## 已完成

- 医务员工工作台：今日工作顺序、个人用药登记留痕、巡诊/医嘱/用药/健康档案/医护交接等常用入口。
- 医务部长工作台：部门今日运行指标、风险优先任务队列、高风险长者、审批与医务任务协调入口。
- 员工版只展示能够由登录账号可靠限定的个人数据；个人任务口径缺失时使用 `--` 和明确空状态，不以部门汇总冒充个人待办。
- 部长版复用现有医务汇总和统一任务接口，不新增或伪造后端业务结构。
- 普通员工不再从工作台进入部门级统一任务中心；该入口仅在部长视图出现。
- 状态同时使用文字与符号表达，按钮保留清晰焦点状态，并适配常见办公屏幕。

## 数据源

- `/api/health/medication/registration/page`：员工本人当天用药登记记录，按当前登录用户名 `nurseName` 精确过滤。
- `/api/medical-care/workbench/summary`：部长版部门今日运行汇总与高风险长者。
- `/api/medical-care/workbench/unified-tasks`：部长版部门风险任务预览。
- 现有路由复用：巡诊/巡检、医嘱、用药登记、健康档案、医护交接、设备告警和审批。

## 数据范围与后端缺口

- 医务汇总与统一任务接口当前是机构/部门口径，不支持可靠的当前医务人员过滤。员工工作台有意不调用这两个接口，防止跨人员数据被标成“我的任务”。
- 巡诊、医嘱和用药任务列表当前缺少统一的登录用户/责任人数据范围参数。后续需由后端补充当前用户范围校验，接入后再替换员工版 `--` 指标和提示。
- 后端暂无按医务人员聚合的任务分配与完成情况接口。部长版明确显示“数据待接入”，不从有限任务预览推算人员绩效。
- 当前用药登记可按 `nurseName` 精确查询，任务完成时后端使用登录用户名留痕，因此员工版仅将该结果作为安全的个人记录切片。
